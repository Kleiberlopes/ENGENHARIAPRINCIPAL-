O que é este sistema

MVP de orquestração de agentes de marketing no modelo Cérebro e Executores. O Agente Cérebro recebe a meta do CEO, roteia e delega tarefas aos executores (Pesquisa → Copy → Tráfego). O lead percorre o funil de vendas (Captação → Educação → Conversão) com o Agente Comercial, é faturado no Checkout, e o Agente Analista calcula ROI, CAC e Conversão, devolvendo o relatório ao Cérebro para uma nova decisão — fechando o loop de feedback.

Pontos fortes (para apresentar aos sócios)
  • Separação clara de responsabilidades — novo agente não mexe no Cérebro, só no mapeador do executor.
  • Loop de feedback real — Analista → Cérebro fecha o ciclo; o sistema decide a próxima rodada, não é pipeline linear.
  • Contratos tipados — Pydantic em toda fronteira; Swagger se auto-documenta.
  • Ponto único de troca de comunicação — função interna ↔ HTTP local mudando 1 função.
  • Persistência desacoplada — trocar SQLite por Postgres = mexer só em database/db.py.
  • Auditoria completa — cada passo vira ExecutionLog (terminal + tabela SQLite).
  • Testável de ponta a ponta — test_flow.py valida o ciclo com asserts, sem servidor.

Decisões de design que sustentam a apresentação

  • Pipeline — brain.run_pipeline() encadeia executores com contexto.
  • Strategy / injeção — Cérebro recebe o executor, não conhece a implementação.
  • Adapter — _internal_executor isola a forma de chamar agentes.
  • Repository leve — toda persistência atrás de Database.
  • Máquina de estados — transições do funil controladas e auditáveis.
  • DTOs — schemas.py como contrato único entre módulos.
Pontos fracos & riscos (honestidade técnica)
#PontoPor que importaGravidade
1Simulações determinísticas (intenção por substring; venda por i%5)Não é IA de verdade; frases fora do dicionário caem no fallbackAlta (produção)
2Roteamento por palavra-chave frágilSinônimos, typos e metas mistas quebram a rotaMédia
3Sem autenticação/autorizaçãoInaceitável se expor fora de localhostAlta (se expor)
4DB singleton com check_same_thread=FalseRisco de race em múltiplos workers uvicornMédia
5Sem testes automatizados formais (pytest/CI)Sem regressão garantida ao evoluir o códigoMédia
6Estado do Cérebro em memóriaRestart perde contexto da rodada (DB guarda, objeto não)Baixa
7Sem handler global de errosException vaza como 500 sem corpo padronizadoMédia
8Log via printProdução exige logging estruturado (níveis/arquivo)Baixa
9Tráfego/orçamento inventadoNão integra Meta/Google Ads reais — placeholderAlta (uso real)
10Sem migrations de schemaTabela mudou, DB antigo incompatívelMédia
11Funil sequencial em loop10 mil leads ficam lentos; sem assíncronoBaixa (MVP)
12ROI usa orçamento fixo da metaNúmeros consistentes internamente, mas não batem com mídia realMédia
Roadmap para produção

Curto prazo — endurecer o MVP

  • Logging estruturado no lugar dos print
  • Handler global de erros (JSON padronizado)
  • Testes com pytest + TestClient do FastAPI
  • Chave de API simples mesmo que só localhost
  • Migrations leves de schema

Médio prazo — IA de verdade

  • Intenção do Comercial → classificador (LLM ou sinonimos)
  • Roteamento do Cérebro via LLM com schema validado
  • Agentes via HTTP interno (cada um = serviço)
  • Fila/assíncrono para funil em massa

Longo prazo — escala

  • SQLite → PostgreSQL
  • Integração real Meta Ads / Google Ads API
  • Dashboard de métricas ao vivo
  • Multi-tenant (vários CEOs/projetos)
